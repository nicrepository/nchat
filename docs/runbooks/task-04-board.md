## Fluxo de uso do board

Status sugeridos:

- `Backlog`
- `Ready`
- `In Progress`
- `In Review`
- `Blocked`
- `Done`

Regras:

- Toda tarefa deve estar vinculada a um epico.
- Toda issue do MVP deve ter milestone `MVP Interno`.
- Toda issue deve ter prioridade.
- Toda issue deve ter label de tipo.
- Toda issue deve ter label de epico quando aplicavel.
- Nada entra no MVP se nao estiver no cronograma ou criterio de aceite.
- Bugs criticos e issues de seguranca tem prioridade sobre feature nova.

## Pendencias manuais

- O campo nativo `Status` do GitHub Project contem `Todo`, `In Progress` e `Done`. Os status sugeridos `Backlog`, `Ready`, `In Review` e `Blocked` devem ser adicionados manualmente na UI caso o fluxo precise dessas colunas.
- A opcao existente do campo `Epic` para o EPIC-04 esta como `EPIC-04 Arquivos Preview e ClamAV`, sem virgula. A issue e a label permanecem com o titulo correto.
- A API de milestones do GitHub retornou `due_on` como `2026-08-17T00:00:00Z` e `2027-02-13T00:00:00Z`, embora a intencao do planejamento seja 17/08/2026 e 13/02/2027. A UI do GitHub trata milestone como data, sem horario operacional relevante.
